# 图片生成计时

插件启动后自动包装 ComfyUI 执行接口，工作流继续使用原有节点。实现基线为 ComfyUI 0.37.0；图片参数解析版本为 3，计时结构版本为 1。

## 计时口径

- 总耗时包围 `PromptExecutor.execute` 原调用，不含排队、后台计时嵌入和索引。排队时间单独保留。
- 采样区间包围 `KSAMPLER` 的实际算法调用，包含算法初始化、预览及等待；单位为毫秒，使用单调高精度时钟。不逐步同步 GPU。
- 迭代数取算法回调中去重的连续迭代编号。自适应算法、缺少完成信号或未覆盖节点保留缺失原因。失败和中断记录完整状态，顶部仅显示成功任务。
- 平均速度为采样累计毫秒数 ÷ 实际迭代数 ÷ 1000，单位为 `s/it`。多次采样累加，批量图片共享任务值。
- 节点调用记录列表索引、动态节点编号及父区间。异步函数等待完成；同步函数返回异步任务时跟踪任务完成回调。直接子区间按时间并集扣除后得到 `self_ms`，节点累计耗时与任务总耗时分别保存。

## 覆盖与边界

节点分类来自 `metadata/registry.py` 的 `timing` 字段，完整节点表生成在 [节点支持清单](METADATA_SUPPORT.md)。同步、异步、列表输入与动态执行节点均通过实际节点函数记录，缓存节点保留缓存状态。

标准模型加载、LoRA 应用、文本编码、输入图像、控制条件、VAE 编解码、放大及保存记录节点调用；模型文件读取、检查点/扩散模型/文本编码器加载、标准 LoRA 应用、显存准备和采样算法另有内部区间。LoRA 的延迟权重应用可能发生在显存准备或采样区间内，记录保留实际嵌套关系。

第三方节点绕过标准内部接口时保留节点总耗时，登记 `node_only` 或注册表中的覆盖限制；未登记节点可能包含自行实现的采样，因此抑制完整采样汇总。自行创建且不传递上下文的线程无法归属时，不将其混入其他任务。单调时钟仅在同一进程、同一任务内比较，持久化后使用已完成的相对区间和时长。

## 存储与无损嵌入

- SQLite 的 `timing_tasks` 保存完整任务，`timing_files` 保存文件身份、输出节点、完整记录、写入状态及错误。文件身份包含大小、纳秒修改时间、文件编号及 SHA-256。
- PNG/APNG 使用 UTF-8 `iTXt` 的 `comfyui_browser_timing`；原 `prompt`、`workflow`、`comf`、压缩图像与动画块逐字节保留。
- WebP 使用 XMP 命名空间 `urn:comfyui-browser:timing:1`，保留其他属性及原 EXIF、图像、动画块，更新 RIFF 长度、填充和 VP8X 标志。
- 图片包含任务区间、完整性、实际迭代、节点与内部区间及输出关联。版本 1 的新增可选 `output` 字段包含文件名、输出节点和嵌入前内容摘要，不含绝对路径。
- 写入采用同目录临时文件、重新解析与块校验、身份复核、原子替换。图片索引提交与写入共享文件锁，刷新仅更新元数据及文件字段，保留标签。
- 临时文件占用按 2、4、8、16 秒退避，最多尝试 5 次。重启恢复未完成写入；`/browser/files/metadata?...&refresh=1` 可重新尝试因文件占用失败的嵌入，使用同一份原计时。
- 元数据上限 4 MiB、容器上限 512 MiB；超过上限或无法安全修改时保留数据库完整记录。XMP 仅接受可安全解析的 UTF-8 XML，禁止 DTD 和实体。未知计时版本保持原样。
- ComfyUI `--disable-metadata` 或其他图片格式使用数据库记录。缓存返回的旧图片、临时预览文件不盖章。普通复制和收藏保留文件内计时；重编码工具可能清除元数据。

## 读取与显示

`/files/metadata` 的 `formatted_info.generation_timing` 返回版本、来源、完整性和汇总，侧栏不接收区间明细。文件内有效记录优先，数据库回退要求文件身份完全一致。计时读取独立于执行图；旧图片没有可信记录时隐藏耗时。

顶部仅增加总耗时、采样和平均速度。原值小于 60 秒显示秒，否则显示分钟，最多两位小数；小于显示精度的正数显示 `<0.01`。零迭代或未知迭代隐藏速度，全缓存任务隐藏采样与速度。悬停标签显示范围和计算方法。

详情与列表共用请求订阅；`timing_pending` 使执行图解析完成后的详情继续等待嵌入，完成或关闭页面后停止轮询。

## 维护与验证

```text
python -m unittest discover -s tests -v
python scripts/metadata_support.py --check
pnpm --dir web-ui test
pnpm --dir web-ui build
python scripts/timing_e2e.py cold
```

真实验收脚本要求本机 ComfyUI 在 8000 端口、队列空闲且已有 `dreamshaper_8.safetensors`。支持 `cold`、`warm`、`batch`、`multi`、`cached`、`formats`、`reload`；`multi` 后紧接 `cached` 验证缓存。脚本保留工作流、执行图及历史响应到 `.timing-e2e`，图片保存于输出目录的 `comfyui-browser-timing-e2e`。运行时缓存压力可能导致节点重新执行，以真实节点调用和缓存事件为准。
